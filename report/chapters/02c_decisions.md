## 技术路线中的关键设计决策

最后，把本章介绍的方法与本项目的具体选择总结为表 @tab:decisions。每一项都列出了备选方案与取舍理由，第三章将从“问题求解”的角度对其中几项做更深入的分析。

::tab decisions | 关键设计决策汇总

| 决策点 | 本文选择 | 备选方案 | 取舍理由 |
|---|---|---|---|
| 棋盘 | 标准 10×10 | 6×6、8×8 小棋盘 | 标准棋盘是文献与比赛的通用设置，结论更有参照意义 |
| 走法表示 | 整数编码 + 预计算射线 | 位棋盘 | 实现简单，开局 2176 个着法的生成只需约 10 微秒 |
| 评估函数 | Lieberum 特征 + 阶段线性插值 | 神经网络；原始非线性阶段函数 | 线性形式可以直接用 Texel 方法学习，速度快、可解释 |
| α-β 框架 | PVS + 迭代加深 + 置换表 | MTD(f)、SSS* | PVS 实现简单且足够高效 |
| 着法排序 | 可分离评估（移后 + 射箭分别评估） | 廉价规则分数；逐一完整评估 | 前者质量差，后者太慢；可分离评估兼顾两者 |
| 前向剪枝 | 束宽 8（根结点 30） | 全宽；空着裁剪 | 分支因子上千，不剪枝只能搜 2 层 |
| MCTS 展开 | 渐进展开 + 可分离评估顺序 | 标准 UCT（全部展开） | 根结点上千个子结点，标准 UCT 的树长不起来 |
| MCTS 选择 | PUCT（启发式先验） | UCT、RAVE | 先验提供软剪枝；RAVE 的统计量在亚马逊棋中很难积累 |
| 模拟策略 | 随机 4 步 + 评估截断 | 随机下到终局 | 随机终局结果的信息量很低（Lorentz 等人的经验） |
| 残局 | 共用的贪心填格策略 | 残局求解器 | 不在本文研究范围；保证比较集中在争夺阶段 |
| 学习 | 线性策略 + Texel | 深度网络自对弈 | 算力限制；可在单机分钟级训练 |
| 运行环境 | 浏览器 Web Worker | 服务器端引擎 | 满足“HTML 展示、无需安装”的要求 |
| 评价 | 配对开局 + Elo + 自助法 | 标准初始局面对弈 | 消除先手优势与确定性带来的偏差 |

## 本章小结

本章给出了“共享知识层 + 两类搜索框架 + 两种学习组件 + 统计评价”的技术路线。知识层用后距离与王距离定义领地评估，并用“可分离评估”在 1—2 毫秒内给全部着法排序；α-β 搜索以 PVS、迭代加深、置换表、杀手与历史启发提高效率，用束宽剪枝应对上千的分支因子；MCTS 以渐进展开、PUCT 先验与评估截断适应亚马逊棋的大分支因子；分隔后的残局交给一个所有智能体共用的填格策略；学习组件分别从自对弈数据中学习走子策略与评估权重；评价方面以配对开局、Bradley–Terry 模型与自助法为核心。相关研究综述表明，本文用到的算法都有成熟的文献基础，本文的价值在于统一实现与系统比较。下一章将从“智能问题求解”的角度，进一步分析这些设计背后的问题建模与权衡。
